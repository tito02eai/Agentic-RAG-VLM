# r5：执行能力感知的接触恢复与多证据放置

本轮在论文检索—约束—反思框架上作工程扩展，保留 r4 的全部原始结果。
目标是修复已知底层停止原因，并检验记忆参数在不同接触条件下是否仍可靠。
不是论文原始实验、完整 benchmark 测评或真机验证。

## 改进与不变的判据

1. **限位附近有界 IK 精修。** 常规 DLS 停滞后采用有界 trust-region 最小二乘，
   仍要求位置误差 <0.5 mm、旋转误差 <0.015 rad、距关节限位至少 0.001 rad。
   在独立规划状态中求解，不改动物理仿真关节状态。不可达点仍拒绝。
2. **多证据的放置支撑确认。** 原严格卸载判据保留。
   对部分卸载但未达原阈值的状态，采用顶视/侧视校准 RGB-D，
   检查目的地区域的可见上表面或桌面附近的下边界、两次观测稳定性和接触力转移。
   只有这些证据成立才允许每次 0.5 mm、最多三次的微量松指，
   且负载降至参考值 15% 以下、可见支撑稳定后才能完全释放。
   为解决曲面抓持时小于毫米的悬空，允许在标称末端高度下最多再下降 1 mm，
   以 0.25 mm 细步执行；标称最低指垫净空约 2.2 mm，原碰撞保护持续启用。
3. **与实际执行能力匹配的接触恢复。** 原三级规则在第二次失败时切换手型，
   当前平行夹爪不能执行未经验证的 pinch/side，必须拒绝。
   新策略仅对已观察到的 slip、语义脆弱性 <=0.25 的对象，
   在释放、撤离、两次新 RGB-D 确认之后进行每次 20% 的力上限修正，
   最多三次且电机力上限不超过 1.6 N。没有绕过执行器能力检查或假装执行 L2 手型。
   非 slip 类型仍交给原分类策略；不支持的动作停止。
4. **失败记忆失效。** 从会话记忆获得的参数一旦发生确认的夹持失败，
   使该类别条目失效并记录原因、来源和失败参数。
   只有完整放置并通过最终验证后，才能写回新成功经验。

最终完成标准保持 r4：各目标目的地误差 <25 mm、释放且桌面支撑、
每个目标高于 10 cm 的双侧接触抬升 >0.5 s、堆叠时先移走上层物体、
无保护物/机械臂禁入接触、目标接触穿透 <3 mm、其他物体位移 <15 mm，
以及框架完成状态。未通过任一项均不算完整完成。

## 新冻结批次

`configs/robust_sim_qualification.json` 定义十个新种子 500–509，
500–504 为堆叠整理，505–509 为平铺整理。每种子三个配对条件：

- `mixed_enhanced`：改进底层、接触反馈调参、记忆开启。
- `mixed_paper`：同一改进底层、重建的原三级恢复规则、记忆开启。
- `mixed_no_memory`：改进底层、接触反馈调参、记忆关闭。

共 30 案例，按种子交错运行三个条件，每例只运行一次。
每个条件使用相同种子的完全相同场景 XML，每个案例从空会话记忆开始。
录制固定种子 500、505，在每个条件下各一段，不根据成功与否选片。
原失败种子 101/103 属于回归测试，开发种子 20–25 不计入新批次。

场景是两个方块、一个品红色圆柱、三个独立目的地和绿色保护容器。
初始位置独立扰动约 12–15 mm，目的地独立扰动 12 mm，保护物扰动 8 mm。
每个目标的质量独立采样 55–75 g，物体摩擦独立采样 0.6–1.0。
**MuJoCo 的滑动摩擦合并使用较大值，指垫摩擦为 0.7，因此有效滑动摩擦至少为 0.7。**
采样的质量/摩擦仅保存到私有评估元数据，不输入规划器、模型提示词或恢复策略。
形状尺寸属于已声明的公开几何配置；物体仍通过颜色候选和真实 VLM 判断身份。
圆柱没有专门训练经验，HAA-RAG 可通过共同 superclass/可供性检索原成功记录；
本批次没有独立的其他检索器对照，不能据此宣称 HAA-RAG 优于其他检索方法。

MuJoCo 3.2.2、2 ms 时间步、elliptic cone、10 次 NoSlip、理想重力补偿和近似碰撞几何保持不变。
支持感知的图像、深度、相机参数和微量松指记录全部落盘，供离线复核。

## 模型与运行

本轮使用独立恢复的本地 Qwen3.5-4B NF4 服务，不复用退出的 18070 端点。
服务只监听 localhost，串行处理真实图像请求，返回实际权重哈希身份。
CLIP ViT-L/14 服务仍为 18072。权重不随源码分发。
最新扩展仿真入口默认使用 18074；历史入口仍可用 `--endpoint` 显式选择服务。

```bash
# 独立 GPU 推理环境：已验证 torch 2.11.0+cu129 / transformers 5.13.1 /
# bitsandbytes 0.49.2；仿真环境仍使用 configs/extended_sim_dependencies.txt。
python scripts/serve_local_vlm.py \
  --model-path /absolute/path/to/Qwen3.5-4B --port 18074 --quantization nf4

MUJOCO_GL=egl python scripts/run_extended_benchmark.py \
  --config configs/robust_sim_qualification.json \
  --endpoint http://127.0.0.1:18074/v1/chat/completions \
  --model /absolute/path/to/Qwen3.5-4B \
  --output /absolute/path/to/new_r5_batch
python scripts/audit_extended_benchmark.py /absolute/path/to/new_r5_batch
```

运行前冻结源码、知识库、配置及模型身份，并在每个案例前核验服务身份不变。
服务预检失败则停止批次；已开始案例中的接口故障保留，单独分类为基础设施失败，
不能作为算法失败后删除重跑。模型和 CLIP 原始输出均留存。

## 结论范围

比较的是本项目中原固定恢复规则与支持的接触反馈策略，共享同一个改进底层，
不是重新实现所有原论文实验后宣布超越原论文。
分别报告完成率、失败原因、记忆失效次数、实际尝试和模型调用；
效率比较只在双方均完成的配对上计算，并列出排除案例。
异质物体上复用未必总有收益，允许负迁移并如实保留。
依然没有开放世界分割、灵巧手、跨会话长期记忆或真机力控的物理验证。

## 独立追加：身份冲突复核

首批冻结案例 seed 500 的多图输出把红色遮挡边缘和绿色容器均标为 `vase`，
严格校验正确停止。该失败不删除、不改成成功。
据此新增 `--grounding-repair`：身份重复、缺失、unknown 或不支持时，
让同一真实模型逐个重新查看对应的原始候选图，最多两轮、每观测最多六次调用。
禁止按候选索引、颜色规则、仿真 ID 或剩余标签排除法强行填身份。
无法消除的冲突仍停止；unknown 仍可导致任务缺失而停止。

`vlm_response.json` 保留第一次原始回答；`identity_review_*.json` 保存每次真实复核，
`grounding_decision.json` 分开记录最终有效标签和图像/初始回答哈希。
CLIP 检索和 RGB-D 定位只在通过校验后绑定到有效实例标签。

追加试验由 `configs/grounding_sim_qualification.json` 另行冻结，
新种子 600–604、两个配对条件共十例，底层、反馈恢复和记忆完全相同，
仅比较复核开启/关闭。固定录制种子 600。已知 500 仅用于额外回归，不计入这十例。
若新的五个种子中没有身份冲突，也如实报告没有观察到完成率收益。

另外修复推理计数的审计口径：身份校验失败前，模型回答已落盘但尚未生成有效感知回执。
旧运行器只数有效回执，会漏计这些回答。新运行器按实际保存的回答计数；
旧批次 `summary.json` 原样保留，后处理另外报告原计数与完整回答计数，不能静默改写原数据。

后处理还检查末态的时间对齐：旧日志每 20 ms 采样，新增观测探测会使末态落在采样间隙。
旧末态若落在采样间隙，不将两个不同时刻的坐标当作精确快照比较；
要求时间差不超过 20 ms，最后采样和报告末态均满足同一个 25 mm 目的地判据，
且最后采样存在桌面支撑。warnings 列出时间差、位置差和“未精确核验最终时刻坐标”。
不改变物理任务成功阈值，也不宣称这些案例已完成逐位末态核验。
后续源码保存时直接追加实际末态快照，不推进或修改物理状态；
已有冻结批次的轨迹不补写、不覆盖。

## 冻结批次之后的保守保护修复

主批次 seed 502 的圆柱滑脱暴露出：原来目标/桌面穿透只在最终评分中判失败，
没有立即中止积分。最终源码增加每个 2 ms 步之后的硬停止，首次观察到 >3 mm 的
目标/桌面穿透或非有限状态就终止，不继续生成已无效的动作轨迹。
这不能保证软接触没有亚毫米穿透，也不能撤销造成第一次超限的那个积分步。
已出现的失败不会因此改成成功，两个批次的原始数据和源码快照保持原样。
这项后续修复单独做撞击反例测试及已知 seed-502 回归，未宣称已用于原 40 个案例。

当前放置几何工具使用已知水平桌面 z=0，不处理未知倾斜支撑面。
旧 `placement_unload_probe.normal_load_before_n/after_n` 字段实际记录竖直承载力，
法向夹持力另见 `tactile.normal_force_n`；不要将两者混用。
